PHASE 2 - LE JOUR DE LA MISE EN LIGNE (étape D, avant l'import)
  Le site est arrêté de toute façon : on change aussi
    - le mot de passe MySQL de l'application (utilisateur du .env) :
        NOUVEAU=$(openssl rand -hex 20)
        docker compose exec db sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "ALTER USER \"$MYSQL_USER\"@\"%\" IDENTIFIED BY \"'"$NOUVEAU"'\"; FLUSH PRIVILEGES;"'
        sed -i "s|^DB_PASSWORD=.*|DB_PASSWORD=$NOUVEAU|" .env
    - la clé Django :
        sed -i "s|^SECRET_KEY=.*|SECRET_KEY=$(openssl rand -base64 48 | tr -d '\n/+=')|" .env
  Le nouveau docker-compose.yml limite aussi le site (8000) au serveur.

3. ÉTAPES
---------------------------------------------------------------------
IMPORTANT : la base (étape D) et le code (étape E) doivent être mis en
ligne l'un juste après l'autre. Entre les deux, l'ancien code tournerait
sur la nouvelle base et le site afficherait des erreurs.

A. Envoyer le code sur une branche, sans mise en ligne
   [x] FAIT le 09/11/2026 : branche « mise-a-jour » (commit 2527170)
       poussée depuis C:\Users\citoyen\Desktop\SiteDFmac ; Pull Request
       ouverte vers main ; tests GitHub au vert (Python 3.11 et 3.12).
       NE PAS FUSIONNER avant le jour de la mise en ligne.
       Toute nouvelle modification de « bendingiron » doit être recopiée
       dans SiteDFmac puis poussée sur la même branche.
   - copier les modifications du dossier de travail vers SiteDFmac
     (sans .env, base SQLite, medias/, __pycache__) ;
   - vérifier la liste des fichiers (git status) ;
   - pousser une branche « mise-a-jour » : GitHub lance les tests,
     SANS déployer (le déploiement ne se fait que sur main).

B. Configurer le nouveau déploiement GitHub
   Le nouveau workflow se connecte en utilisateur « deploy » avec une
   clé SSH (l'ancien utilisait root et un mot de passe).
   Secrets GitHub à créer (Settings > Secrets and variables > Actions) :
     VPS_IP           adresse IP du VPS
     VPS_USER         deploy
     VPS_SSH_KEY      clé privée ed25519 de l'utilisateur deploy
     VPS_KNOWN_HOSTS  résultat de : ssh-keyscan -H <IP_DU_VPS>
   (VPS_SSH_PASS n'est plus utilisé.)

C. Compléter le .env du VPS (/var/www/bendingiron/.env)
   Comparer avec .env.example. Variables à vérifier :
     DJANGO_SETTINGS_MODULE=SiteDFmac.production
     SECRET_KEY, DEBUG=False
     ALLOWED_HOSTS, CSRF_TRUSTED_ORIGINS, SITE_URL
     DB_ENGINE=mysql, DB_NAME, DB_USER, DB_PASSWORD, DB_HOST=db, DB_PORT=3306
     MYSQL_ROOT_PASSWORD
     EMAIL_HOST, EMAIL_HOST_USER, EMAIL_HOST_PASSWORD
     OM_BASE_URL, OM_CONSUMER_KEY, OM_CONSUMER_SECRET, OM_API_USER,
     OM_API_PASSWORD, OM_PIN, OM_CHANNEL_USER_MSISDN,
     OM_NOTIF_URL=https://www.bending-iron.com/paiements/notif/orange/
     GUNICORN_WORKERS=4, LOG_LEVEL=INFO
   NE PAS mettre PAIEMENT_SIMULATION=True en production (de toute
   façon ignoré quand DEBUG=False).

!! AVANT D et E : sur le serveur, « docker compose » (avec un espace)
   n'existe pas, seul « docker-compose » (avec un tiret) fonctionne.
   Or deploy.sh et les commandes ci-dessous utilisent « docker compose ».
   Au choix : installer le plugin Compose v2 sur le VPS
   (paquet docker-compose-plugin), ou remplacer « docker compose » par
   « docker-compose » dans deploy.sh et dans les commandes ci-dessous.
   Vérifier avec : docker compose version ; docker-compose --version

D. Jour de la mise en ligne - remplacer la base (sur le VPS)
   1. Copier le fichier sur le VPS, par exemple :
        scp bendingiron_db_pour_production_2026-11-09.sql deploy@<IP>:/var/www/bendingiron/
   2. Arrêter le site (la base reste allumée) :
        cd /var/www/bendingiron
        docker compose stop web
   3. Vider la base et la recréer en utf8mb4 :
        docker compose exec db sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "DROP DATABASE \`$MYSQL_DATABASE\`; CREATE DATABASE \`$MYSQL_DATABASE\` CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci; GRANT ALL ON \`$MYSQL_DATABASE\`.* TO \"$MYSQL_USER\"@\"%\"; FLUSH PRIVILEGES;"'
   4. Importer le fichier :
        docker compose exec -T db sh -c 'mysql -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE"' < bendingiron_db_pour_production_2026-11-09.sql
   5. Vérifier (62 tables attendues) :
        docker compose exec db sh -c 'mysql -u"$MYSQL_USER" -p"$MYSQL_PASSWORD" "$MYSQL_DATABASE" -e "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema=DATABASE();"'
   6. OBLIGATOIRE après chaque import d'une base venant de Windows
      (trouvé le 10/11/2026 : erreur 500 dès qu'on se connecte,
      « Table 'bendingiron_db.usesOrders_cart' doesn't exist ») :
      WAMP/MariaDB sous Windows écrit les noms de tables en minuscules
      (usesorders_cart), alors que MySQL sous Linux distingue les
      majuscules et que Django attend usesOrders_cart. MySQL 8 ne peut
      pas ignorer la casse après sa création : il faut renommer les
      tables avec le script outils/corriger_casse_tables.py :
        docker-compose exec -T web python manage.py shell < outils/corriger_casse_tables.py
          -> affiche la liste (10 tables usesorders_* le 10/11/2026)
        docker-compose exec -T -e APPLIQUER=1 web python manage.py shell < outils/corriger_casse_tables.py
          -> doit afficher « RENOMMAGE FAIT », puis relancer la 1re
             commande : « A renommer : 0 | Introuvables : aucune »
      Faire une sauvegarde (mysqldump) avant.

E. Juste après - mettre le code en ligne
   Fusionner la branche « mise-a-jour » dans main sur GitHub.
   Le workflow : tests -> copie du code sur le VPS -> docker compose up
   --build -> migrate (rien à faire : la base correspond déjà au code)
   -> collectstatic -> démarrage.

F. Vérifications après la mise en ligne
   - le site s'ouvre, connexion d'un compte, panier ;
   - /sitemap.xml répond ;
   - admin /larue/ > Boutique : saisir les vraies valeurs (prix à la
     tonne, PrT, poids au cm, coefficients, soudure, constantes Ldf) ;
   - page du cadre carré : prix et dessin.

En cas de problème : réimporter la sauvegarde de la production faite
avant l'étape D (même méthode qu'en D3 / D4) et remettre l'ancien code
(revenir sur main au commit 0e1b628 « cache des boutons d'ajout panier »).
